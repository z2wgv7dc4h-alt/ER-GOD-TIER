# All-Knowing — architecture (Task 137)

Current-app architecture. For the product brief and task history see `HANDOFF-CLAUDE.md`;
for the data census see `docs/DATA-CATALOG.md` (regenerate with `npm run data:catalog`);
for the map engine see `docs/MAP-ENGINE.md`. The older root `ARCHITECTURE.md` is a
kernel-only note; this file supersedes it for the shipped app.

---

## 1. Kernel and state

- `src/types.ts` — `Character`, facts, shots, modules.
- `src/state.tsx` — the single `Workspace` provider. `Character` lives here; every
  module projects it. Mutations go through `setCharacter` or `applyFacts` /
  `denyFacts` / `clearFact`.
- Fact language `kind:slug`; state `true | false | unknown`. Evidence → facts runs
  through `src/lib/infer.ts` (`closeWorld` walks `catalog.implies` + the authored
  `inferChains`), so a named read (OCR hit, warp paste, typed item) implies
  downstream facts. Derived facts carry `source: 'inference'`.
- Persistence: `all-knowing.vault.v1` (profiles + UI), packets
  (`*.all-knowing.json`), and device settings `all-knowing.settings.v1`
  (`src/settings/store.ts`: text size, reduce motion, spoilers, haptics, landing).
  `src/settings/SettingsEffects.tsx` mirrors text size / reduce-motion onto
  `document.documentElement`'s `data-*` attributes, which the CSS keys off.

## 2. Shell — four sections

`src/App.tsx` is a thin router; chrome lives in `src/shell/`.

| Section | Sub-views | Job |
|---|---|---|
| Tarnished | overview · update · profiles | character, progress, saves, profiles, settings |
| Journey | now · map · quests | what now / where / working towards |
| Library | search · builds · kit · pvp · guides | what do I know / what should I build |
| Gideon | — | full chat (also docks on wide desktops) |

Phone gets four bottom tabs; desktop gets the header + sub-tabs. `#/section/sub`
hashes drive reload/back, and the legacy `setModule` ids map onto the four
sections. Entity pages are the `?e=<factId>` overlay (`src/library/EntityOverlay.tsx`
→ `src/library/EntityPanel.tsx`), one template used by every list, card and search
hit.

## 3. Entity graph and index

- `src/lib/entityGraph.ts` — the runtime graph of every authored fact plus anything
  registered at load (`registerEntityGraphData`).
- `public/sourced/entity-index.json` — the build-time enriched index (NPCs,
  locations, enemies, items, quest beats, combat stats, images, placements),
  generated by `npm run index:entities` (`scripts/build-entity-index.mjs` →
  `src/lib/entityIndexBuild.ts`). Read at runtime by `src/lib/entityIndex.ts` /
  `src/lib/entityEnrich.ts`.
- Quest lines are the authored `src/knowledge/storylines.ts`; the wiki DB's ordered
  NPC steps are matched onto those beats by `src/lib/questStepMatch.ts` (Task 137:
  a match requires a location or item signal, otherwise the wiki step stays a
  separate ordered step).
- `src/lib/aliases.ts` + `public/sourced/aliases.json` canonicalise engine ids
  (`grace:{row}`, `bossflag:{n}`) onto authored slugs.

## 4. Wiki corpus and search

- `public/sourced/wiki/pages-*.json` + `manifest.json` — the whole Fandom snapshot
  (4,939 pages), one chunk per ~120 pages. `search-index.json` + `search-*.json`
  are the prebuilt inverted index.
- Runtime readers: `src/lib/wikiSearch.ts` (full-text search),
  `src/lib/wikiSections.ts`, `src/library/WikiSearchResults.tsx` (shown beside a
  Library search), and `src/lib/gideonWiki.ts` (grounds Gideon's wiki answers).
- `src/lib/gameText.ts` lazy-loads the install's FMG tables (`open/text/`) for
  verbatim item lore and dialogue; `src/lib/dialogueOwners.ts` attributes lines to
  speakers from the game's own ESD/MSB data.

## 5. Advisor and the attack-rating calculator

- `src/lib/advisor.ts` — the pure recommendation engine (`advise`, `detectBuild`,
  gear picks, upgrades). `src/lib/verdict.ts` holds the pure threshold logic;
  `src/lib/weaponVerdict.ts` the AR-dependent weapon verdict.
- `src/lib/ar.ts` — the Clark attack-rating calculator port; regulation data is
  fetched lazily from `/sourced/regulation-vanilla-v1.17.json` (`loadWeapons`).
- **Task 137 perf split.** The calculator is its own lazy chunk (`ar-*.js`). The
  stat-only model lives in `src/lib/archetype.ts` and the authored gear table in
  `src/lib/gearTags.ts`, so eager UI (the area hub, the entity overlay, the Journey
  "Recommended" card) never imports the calculator. The main entry no longer
  statically imports `src/lib/ar.ts`; Build/Library AR views load it on demand.

## 6. PS5 capture

The app is PS5-first: a player with no save file reconstructs state from screenshots.

- `src/shell/MeSetup.tsx` — the setup wizard (class, stats, map step).
- `src/lib/ps5Status.ts` — parses the status screen OCR (`extractStatus`,
  `mergeStatusReads`, `interpretStatus`): level, runes, attributes.
- `src/lib/ps5Inventory.ts` + `src/lib/ps5Scanner.ts` — inventory grid detection,
  item-name OCR and catalogue resolution (`analyzeFrame`, `defaultItemResolver`).
- `src/lib/ps5Equipment.ts` + `src/lib/ps5Crafting.ts` — equipment-screen parsing
  (weapon + affinity + upgrade, slot stack) and cookbook inference.
- `src/lib/ps5Capture.ts` / `ps5ScannerBrowser.ts` — browser entry points over the
  OCR engine (`tesseract.js`), used by `src/shell/ScanInventory.tsx` (live camera
  scanner) and the setup wizard.
- **Map photo reader** (Task 135) — `src/lib/ps5Map*` + the `MeSetup` map step read
  a photographed map/grace list into discoveries. Kept separate from the inventory
  scanner.
- OCR tests run via the dedicated `vitest.ocr.config.ts` (`npm run test:ocr`) so
  the default `npm test` stays fast.

## 7. Map engine and the atlas

- `vite.config.ts`'s `all-knowing-map-engine` plugin serves the absorbed
  [EldenRingMap](https://github.com/egormagurin/EldenRingMap) engine at `/engine/**`
  — tiles, icons and the `/api/{markers,state,events,saves}` its front-end calls.
  No second process is needed for the live map; `/engine/*` is `NetworkOnly` in the
  service worker so offline detection sees real failures.
- `src/Atlas.tsx` is the map stage: the live engine iframe when it is up, otherwise
  the static plates (`public/sourced/maps/*.jpg`) with grounded pins. The two pin
  sets never mix (`src/lib/atlasSelection.ts`).

## 8. Offline

- `src/lib/pwa.ts` is the single source of the service-worker policy. The app shell
  is precached; `/sourced/**` is served **cache-first from one dedicated bucket**
  (`SOURCED_OFFLINE_CACHE = 'ak-sourced-offline'`).
- Settings → Tarnished → Profiles → **Data & offline** can download **every file**
  under `public/sourced/**` with a progress bar (files + MB). The file list is
  `public/sourced/offline-manifest.json`, generated by `npm run data:offline`
  (`scripts/build-offline-manifest.mjs`). Downloads are resumable (already-cached
  files are skipped) and removable; the panel also shows
  `navigator.storage.estimate()` usage/quota and calls `navigator.storage.persist()`.
  Logic in `src/settings/dataFreshness.ts`.

## 9. Data and tooling

- `docs/DATA-CATALOG.md` — generated census of every source: `npm run data:catalog`.
- `npm run index:entities` — rebuild `public/sourced/entity-index.json`.
- `npm run data:offline` — rebuild the offline manifest.
- `npm run audit:ui` — static UI audit; `npm run crawl:ui` — the click-everything
  Playwright crawl (needs a running dev server; output under `.scratch/ui-crawl/`).
- `npm run test:bundle` — build, then run the bundle-budget guards against fresh
  `dist/` output. `src/lib/bundleBudget.test.ts` skips its `dist/` scans when the
  build is older than the sources, so `npm test` is build-independent.

## 10. Run it on the phone

1. `npm install` once, `npm run cert` once (self-signed cert covering `localhost`
   and the current LAN IPv4s).
2. `npm run dev` — Vite serves `https://<lan-ip>:5173` (and the map at `/engine`).
3. On the phone, open `https://<lan-ip>:5173`, accept the certificate warning once
   (Advanced → Proceed). The secure context is what lets the live camera scanner
   call `getUserMedia`.
4. Install from the browser menu for the offline shell; then Settings → Data &
   offline → **Download everything for offline** for the wiki/search corpus.
   Without a `.cert/` the dev server is plain HTTP and the camera stays blocked.
