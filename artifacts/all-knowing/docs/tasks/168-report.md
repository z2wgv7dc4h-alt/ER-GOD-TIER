## ASSUMPTIONS

- **Generated file.** `questions.json` is produced by `build-gideon-eval.mjs`;
  per AGENTS.md I changed the generator and regenerated instead of hand-editing.
- **`out-of-scope` is a text classifier**, applied deterministically to the
  question string. It keys on request phrasing ("drop me", "trade", "mule",
  "who can join", "anyone able/willing/free/wanna", "can someone help" minus
  lookup/explanation/build), session passwords, and a few off-topic phrasings.
  It is not a per-question id list.
- **"help me find/build/explain X" stays answerable** (it is a data question,
  not a request for another player); only co-op/trade/session/opinion/off-topic
  posts are reclassified. `bug-glitch` keeps its own type (platform/patch
  category) but remains `answerable: false` and is scored honest.
- **Edit distance ≤ 2** (the brief) is used only after exact names fail: a
  two-pass resolve returns exact matches when any exist and consults the
  typo-tolerant pass only otherwise. Without that guard the ≤ 2 threshold
  produced false subject matches and dropped the score to 78.5%; with it the
  result is 84.4%. Single- and double-edit typos ("melania", "placidusax") now
  resolve.
- **Online path unchanged.** `askGrounded`/`askGroundedLimits` run only with no
  key; `loadGroundedIndex()` is awaited only with no key; the wiki guard only
  applies once the entity index is loaded. No online/agent code or token limit
  was touched.
- **`scripts/_diag-gideon.mjs`** (added by the previous run) was removed: it is
  a scratch diagnostic, not part of the brief.
- **`where-is` / `compare`** counts fell slightly; these are the cross-entity
  ambiguities the ≤ 2 pass trades against, not a regression in the new code.
